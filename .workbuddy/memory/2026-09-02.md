# 2026-09-02

## 新增功能：菜单项 ▸ 悬浮即展开下一级（级联子菜单）

需求：菜单项有下一级时，鼠标停在其右侧 ▸ 上自动显示下一级，不用点击。

实现要点：
- `types.ts`：`MenuEntry` 增加 `children?: () => MenuEntry[]`（**懒加载函数**，不是数组），
  避免一次性递归展开整棵标题树；新增设置项 `hoverExpandChildren`（默认 true）。
- `main.ts`：浮层从单层 `popupEl/popupAnchor` 重构为**栈** `popups: PopupLayer[]`
  （`{ el, anchor, level }`，level 0 = 根菜单，子菜单 +1）。核心方法：
  `schedulePopup(anchor, loader, level)` / `openPopup(anchor, entries, level)` /
  `closePopupsFrom(level)` / `repositionPopups()` / `containsPopup(node)` / `closePopups()`。
- 定位：level 0 保持「锚点下方、超出下沿上翻」；level > 0 贴在所属 item 右侧，
  右边放不下翻到左侧，超出下沿则上顶。
- **踩坑**：`mouseenter` 只在进入菜单时触发一次，鼠标在菜单内部移动会被
  `▸` 的 `mouseleave → scheduleHide(220ms)` 误关。解法是给每层 popup 额外绑
  `mousemove → cancelHide()`。
- 切条目收起子菜单：item 的 `mouseenter` 里若 `popups.find(p => p.level === level+1).anchor !== item`
  则 `closePopupsFrom(level+1)`，并清掉待执行的 showTimer。
- 点击 ▸ 仍是「下钻到面包屑末尾」的旧语义，与悬浮展开并存；`hoverExpandChildren` 关闭时退化为只能点击。
- 子菜单 className 为 `bcn-popup bcn-popup-sub`，根菜单仍是 `bcn-popup`——
  测试里 `popup()` 用全等匹配 className，天然只取根菜单，旧用例不受影响。
- 来源 item 加 `.is-open` 高亮，closePopupsFrom 时移除。

验证：冒烟测试 21 → 26 项全过；新增用例覆盖「悬浮展开 / 逐层深入 /
切条目收起 / 点击子菜单跳转并全关」。

## 追加需求：悬浮条目本体即展开（不必瞄准 ▸）+ 开关

需求：项目有下一级时，悬浮到**条目本身**就展开；要有设置开关，默认是不需要悬浮到 ▸。

- 新增设置项 `hoverExpandOnItem`（默认 true）。与已有 `hoverExpandChildren` 组成两级：
  前者是总开关（关掉 = 只能点击 ▸ 下钻），后者决定「条目本体 / 仅 ▸」哪种触发方式。
- `createPopupItem` 的 item `mouseenter` 统一处理：先收起别的条目的子菜单，
  再判断 `hoverExpandOnItem` 决定是否 `schedulePopup(item, children, level + 1)`。
  `▸` 上的 `attachSubmenuHover` 保留——`hoverExpandOnItem=false` 时它就是唯一入口。
  两条路径共用 `schedulePopup`，所以 160ms 延时和切条目收起行为完全一致。
- 设置面板：两个开关联动，总开关关闭时用 `ToggleComponent.setDisabled(true)` 禁用子开关
  （需 `import { ToggleComponent } from "obsidian"`，在 addToggle 回调里保存组件引用）。
- 测试 26 → 28 项全过；新增「默认悬浮条目本体即展开」「关闭开关后条目本体不展开、
  但 ▸ 仍可展开」两条。
