# 2026-09-05

## 面包屑改为「每个视图一条 + 常驻占位」

需求：面包屑要一直占位，不要「退出编辑不显示、进入编辑才显示」来回跳。

根因：旧 `refresh()` 只要 `getActiveViewOfType(MarkdownView)` 拿不到（新建标签页 / 看板 /
非 md 文件等），就直接 `removeBar()`；切回笔记再重建，正文上下跳。

实现：
- `barHost` 单例改为 `bars: Map<contentEl, bar>`；`barEl` 只表示活动视图那条（算吸顶高度、
  下钻后重新弹菜单用）。
- `collectMarkdownViews()` 遍历 `workspace.getLeavesOfType("markdown")`，活动视图排最前。
- **一个笔记视图都没有时不移除**：只 `pruneDetached()` 回收宿主已脱离文档的；
  视图真关闭才 `pruneBars(live)` 回收。这就是「一直占位」的关键。
- id 只给活动视图的 bar（避免多栏重复 id），其余只有 class —— 测试 `barOf()`
  因此从 `c.id === "bcn-bar"` 改成 `className.includes("bcn-bar")`。
- 视图判断用鸭子类型（`file` + `contentEl` + `getMode`）而不是 `instanceof MarkdownView`，
  因为 test 里的 view 是普通对象桩。
- 测试桩 `makeApp` 需补 `getLeavesOfType`（插件现在依赖它）。

## ⚠️ 踩坑（重要，易复发）

`focalKey`（下钻态）是**全局**的，而树是每个文件各自的。渲染某视图时若先取
`const focal = isActive ? this.focalKey : null` 再清理失效值，就会拿**上一篇笔记的 key**
去查当前树 → `byKey.get()` 为 undefined → 链为空 → 面包屑只剩「文件名 › ▸」。

正确顺序：**先** `if (isActive && focalKey && !tree.byKey.has(focalKey)) focalKey = null`，
**再**取 focal。原单视图时代没暴露是因为切文件时 focal 通常已为 null。

排查手法：测试失败时别猜，直接在用例里 `console.log` 中间量（scrollTop / rects / barChildren），
一眼定位。这次靠它很快发现是 focal 而非滚动计算的问题。

验证：冒烟测试 28 → 32 项全过，新增「无活动视图时保留占位 / 多视图各一条 / 关视图后回收」。
